## 部署架构

容器编排包含四个服务，启动顺序：`db`（健康检查通过）→ `redis` → `api`（健康检查通过）→ `web`。

| 服务 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| `redis` | redis:7-alpine | 6379 | Redis 分布式缓存 |
| `db` | mysql:8.0 | 3306 | MySQL 数据库，数据持久化至命名卷 |
| `api` | 自建（.NET 10） | 5000 → 8080 | Minimal APIs 后端 |
| `web` | 自建（.NET 10） | 8080 → 8080 | Blazor Web App 前端 |

```
外部访问:
  Web UI:  http://localhost:8080  →  web:8080
  API:     http://localhost:5000  →  api:8080

容器网络内部:
  web ──▶ api ──▶ db (MySQL)
                ──▶ redis (缓存)
```

## 快速启动

```bash
# 克隆仓库
git clone https://github.com/Larpx/my-college-project.git
cd my-college-project

# 构建并启动所有容器（首次约 3-5 分钟）
docker-compose up -d --build

# 查看容器状态
docker-compose ps

# 查看日志
docker-compose logs -f api
docker-compose logs -f web
```

启动完成后访问：**http://localhost:8080**

> `api` 容器启动时自动执行 `DbInitializer.InitializeAsync()`（CodeFirst 建表）与 `SeedAsync()`（播种默认数据），无需手动迁移。

## 环境变量配置

### api 服务

> 第二轮安全审计后，`Db__ConnectionString`、`Jwt__SecretKey`、`Cors__AllowedOrigins` 在 `appsettings.json` 中均已置空，**生产环境必须通过环境变量注入**，否则启动校验失败。

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `Db__ProviderType` | MySQL | 数据库类型（SQLite / MySQL） |
| `Db__ConnectionString` | （**置空，必须注入**） | 数据库连接字符串（H-5） |
| `Jwt__SecretKey` | （**置空，必须注入**） | JWT 签名密钥，≥32 字符（L-5） |
| `Cors__AllowedOrigins__0` | （**置空，必须注入**） | CORS 白名单来源（M-7，可配置多个 `__0`/`__1`...） |
| `ASPNETCORE_ENVIRONMENT` | Production | 运行环境 |
| `ASPNETCORE_URLS` | http://+:8080 | 监听地址 |
| `ConnectionStrings__redis` | redis:6379 | Redis 连接字符串（**JWT 黑名单 / TOTP 重放保护 / 2FA 速率限制依赖，生产必须配置**） |

### web 服务

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `Api__BaseUrl` | http://api:8080 | 后端 API 基址 |
| `ASPNETCORE_ENVIRONMENT` | Production | 运行环境 |
| `ASPNETCORE_URLS` | http://+:8080 | 监听地址 |
| `Jwt__SecretKey` | （**置空，必须注入**） | JWT 签名密钥，需与 api 服务一致（L-5） |
| `Cors__AllowedOrigins__0` | （**置空，必须注入**） | CORS 白名单来源（M-7） |

### docker-compose `.env` 模板

在项目根目录创建 `.env` 文件（**切勿提交至版本控制**），docker-compose 会自动加载：

```env
# 数据库（H-5：appsettings 已置空，必须注入）
Db__ProviderType=MySQL
Db__ConnectionString=Server=db;Port=3306;Database=attendance;User=root;Password=<强密码>;AllowPublicKeyRetrieval=True;

# JWT 密钥（L-5：必须注入，≥32 字符）
Jwt__SecretKey=<至少 32 字符的随机字符串>

# CORS 白名单（M-7：必须注入）
Cors__AllowedOrigins__0=https://your-domain.com

# Redis
ConnectionStrings__redis=redis:6379
```

> ⚠️ 若 `ConnectionStrings__redis` 未配置，JWT 黑名单、TOTP 重放保护、2FA 失败锁定等功能将不可用，存在安全风险。

## 生产环境注意事项

> 第二轮安全审计（5 HIGH / 7 MEDIUM / 5 LOW）后，以下配置项为**强制要求**，缺失将导致启动失败或安全功能降级。

1. **注入数据库连接字符串（H-5）**：`appsettings.json` 中 `Db:ConnectionString` 已置空，必须通过 `Db__ConnectionString` 注入，启动时校验非空
2. **注入 JWT 密钥（L-5）**：必须通过 `Jwt__SecretKey` 注入至少 32 字符的随机字符串；DEBUG 自动生成的临时密钥**仅限本地调试**
3. **注入 CORS 白名单（M-7）**：必须通过 `Cors__AllowedOrigins__0` 注入允许的前端来源，**禁止使用通配符 `*`**
4. **配置 Redis（M-1 / M-2 / M-3）**：JWT 黑名单、TOTP 重放保护、2FA 失败锁定均依赖 `IDistributedCache`，必须配置 `ConnectionStrings__redis`
5. **配置反向代理 + HTTPS**：在 `web` 前配置 Nginx + HTTPS，启用 HSTS（`SecurityHeadersMiddleware` 在生产环境自动下发 `Strict-Transport-Security`）
6. **CSP 安全头（L-4）**：`SecurityHeadersMiddleware` 自动下发 CSP、HSTS、Referrer-Policy、Permissions-Policy，反向代理需确保这些响应头不被覆盖
7. **修改 MySQL 密码**：通过环境变量覆盖 `Db__ConnectionString` 中的密码，使用最小权限专用账号
8. **移除端口暴露**：生产环境移除 `db` 和 `redis` 的 `ports` 映射，仅保留内部网络
9. **资源限制**：根据服务器配置添加 `deploy.resources.limits`
10. **日志收集**：配置 Serilog sink 写入外部日志系统
11. **审计日志归档（M-5）**：`IAuditService` 记录的审计事件需接入外部日志/审计系统长期保存，满足合规追溯要求

## 学生批量导入流程

第二轮安全审计后（L-2 修复），学生 CSV 批量导入流程：

1. 管理员通过 `/api/v1/users/students/batch-import` 上传 CSV 文件
2. 系统为每位学生调用 `RandomNumberGenerator` 生成 **12 位随机密码**（不再使用统一默认密码）
3. `Student` 实体的 `MustChangePassword` 字段置为 `true`
4. 接口响应返回 `GeneratedPasswords`（学号 → 随机密码清单），管理员需通过安全渠道下发给学生
5. 学生首次登录后，系统返回 `mustChangePassword = true`，引导至 `/force-change-password` 页面强制改密
6. 改密成功后 `MustChangePassword` 置为 `false`，正常使用系统

> ⚠️ `GeneratedPasswords` 清单包含明文密码，管理员应妥善保管，建议改密完成后即销毁；导入异常时响应不暴露 `ex.Message`（M-6 修复）。

## 故障排查

### 容器启动失败

```bash
docker-compose ps           # 查看容器状态
docker-compose logs api     # 查看 API 日志
docker-compose logs web     # 查看 Web 日志
```

### 启动校验失败

日志出现 `配置项 Db:ConnectionString / Jwt:SecretKey / Cors:AllowedOrigins 为空` 异常：

1. 确认 `.env` 文件已创建且包含 `Db__ConnectionString`、`Jwt__SecretKey`、`Cors__AllowedOrigins__0`
2. 确认 `docker-compose.yml` 中 api / web 服务的 `environment` 引用了上述变量
3. 确认 `Jwt__SecretKey` 长度 ≥ 32 字符
4. 确认 `Cors__AllowedOrigins__0` 不是通配符 `*`

### JWT 黑名单 / 2FA 异常

1. 确认 `redis` 容器健康：`docker-compose ps redis`
2. 确认 `ConnectionStrings__redis=redis:6379` 已注入
3. 若 Redis 不可用，登出、TOTP 重放保护、2FA 失败锁定将失效

### 数据库连接失败

1. 确认 `db` 容器健康：`docker-compose ps db`
2. 确认连接字符串中 `Server=db` 与服务名一致
3. 确认 `Db__ConnectionString` 已通过环境变量注入（appsettings.json 已置空）

### Web 无法访问 API

1. 确认 `api` 容器健康：`docker-compose ps api`
2. 确认 `web` 的 `Api__BaseUrl=http://api:8080`
3. 确认 `api` 的 `Cors__AllowedOrigins__0` 包含 `web` 的实际访问来源

### 常用运维命令

```bash
# 停止容器（保留数据）
docker-compose stop

# 停止并删除容器（保留数据卷）
docker-compose down

# 完全清理（含数据）
docker-compose down -v
docker-compose build --no-cache
docker-compose up -d

# 修改代码后重新构建
docker-compose up -d --build api web
```
