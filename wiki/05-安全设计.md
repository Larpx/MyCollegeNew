# 安全设计

> 📖 本文档是 Wiki 的一部分 · [🏠 返回首页](./Home.md)

本项目已通过两轮安全审计修复，第二轮共修复 **17 个漏洞**（5 HIGH / 7 MEDIUM / 5 LOW），覆盖认证与会话、授权与角色、密码策略、审计日志、安全响应头、配置安全等攻击面。

---

## 安全特性总览（17 项修复）

| 编号 | 严重度 | 问题 | 修复方案 |
|------|--------|------|----------|
| H-1 | HIGH | 登录滑块验证码校验完全失效 | `CaptchaToken` 改为必填，`LoginValidator` + `LoginHandler` 强制校验 |
| H-2 | HIGH | BFF `/auth/2fa-complete` 死端点未验证即创建会话 | 删除该端点，2FA 流程由 `/auth/2fa-verify` 与 `/auth/2fa-bind` 完成 |
| H-3 | HIGH | 管理员自删除保护失效（ICurrentUser 类型混淆） | 新增 `SystemUserId` 属性，JWT 新增 `system_user_id` claim |
| H-4 | HIGH | 管理员无法修改自身密码 | `ChangePasswordHandler` Admin 分支兼容 Id/Username 查询 |
| H-5 | HIGH | appsettings.json 硬编码数据库连接字符串 | 连接字符串置空，启动时校验，生产环境通过环境变量注入 |
| M-1 | MEDIUM | TOTP 验证码缺少重放保护 | `IDistributedCache` 记录已用验证码，窗口期内拒绝重放 |
| M-2 | MEDIUM | 2FA 端点缺少速率限制与锁定 | 独立 `twofa` 速率限制（每 IP 每分钟 10 次）+ 5 次失败锁定 |
| M-3 | MEDIUM | JWT 无服务端撤销机制 | `TokenRevocationService` + `/auth/logout` + `jti` claim + `OnTokenValidated` 黑名单检查 |
| M-4 | MEDIUM | TOTP 密钥通过非 HttpOnly Cookie 传输 | 改用 `IDistributedCache` 服务端会话存储 TOTP 密钥/二维码 |
| M-5 | MEDIUM | 敏感操作无持久化审计日志 | 新增 `IAuditService`/`AuditService` + `AuditLog` 实体，应用于敏感操作 |
| M-6 | MEDIUM | CSV 批量导入 `ex.Message` 返回客户端 | catch 块替换为通用错误提示，详细信息保留在服务端日志 |
| M-7 | MEDIUM | CORS 配置过于宽松（AllowAnyOrigin） | 改用白名单，`Cors:AllowedOrigins` 置空，生产环境通过环境变量注入 |
| L-1 | LOW | 密码复杂度要求过低 | 新增 `ApplyPasswordPolicy()` 扩展（8 位+大小写+数字） |
| L-2 | LOW | 学生默认密码可预测 | CSV 导入使用 `RandomNumberGenerator` 生成 12 位随机密码 + `MustChangePassword` 标记 |
| L-3 | LOW | 登录用户存在性时序侧信道 | 用户不存在时执行 dummy BCrypt Verify 对齐耗时 |
| L-4 | LOW | SecurityHeadersMiddleware 缺少安全头 | 新增 CSP、HSTS、Referrer-Policy、Permissions-Policy |
| L-5 | LOW | appsettings.Development.json 硬编码 JWT SecretKey | SecretKey 置空，`UserSecretsId` 配置，DEBUG 自动生成随机密钥 |

## 认证与会话安全

### 登录验证码强制校验（H-1）

- `LoginRequest.CaptchaToken` 改为必填字段
- `LoginValidator` 通过 `NotEmpty()` 强制校验
- `LoginHandler` 在密码校验前调用 `ValidateCaptchaTokenAsync` 验证 token 有效性，失败返回 401

### JWT 黑名单（M-3）

- 登出端点 `/auth/logout` 调用 `TokenRevocationService.RevokeAsync(jti, expiry)`
- 将 `jti` 写入 `IDistributedCache`，TTL = Token 剩余有效期
- `OnTokenValidated` 实时检查黑名单，命中则 401
- **依赖 Redis / `IDistributedCache`**

### 2FA 重放保护与锁定（M-1 / M-2）

- **重放保护（M-1）**：TOTP 验证码验证成功后写入 `IDistributedCache`（TTL 30-90 秒），窗口期内拒绝重放，符合 RFC 6238 §5.2
- **独立速率限制（M-2）**：2FA 端点独立 `twofa` 策略，每 IP 每分钟 10 次，5 次失败锁定临时令牌
- **密钥服务端会话存储（M-4）**：TOTP 密钥/二维码改用 `IDistributedCache` 存储而非非 HttpOnly Cookie

### 时序侧信道防护（L-3）

登录流程用户不存在时执行 dummy BCrypt Verify，消除用户存在性导致的耗时差异，避免通过响应时间枚举有效用户名。

## 授权与角色

### ICurrentUser 与 SystemUserId（H-3）

- `ICurrentUser.UserId`：业务主键（学号/工号/用户名）
- `ICurrentUser.SystemUserId`：统一系统主键（对应 JWT `system_user_id` claim）
- 管理员自删除保护、改密等场景按 `SystemUserId` 比较，解决 Admin 角色类型混淆（H-3 / H-4 同源根因）

### 授权策略

| 策略 | 要求 |
|------|------|
| RequireAdmin | Role=Admin |
| RequireTeacher | Role=Teacher/Counselor |
| RequireStudent | Role=Student |
| RequireCounselor | Role=Counselor |
| RequireDepartmentHead | AuthenticatedUser + `Teacher.IsDepartmentHead` 数据库校验 |

### CORS 白名单（M-7）

- `appsettings.json` 中 `Cors:AllowedOrigins` **置空**
- 生产环境通过环境变量 `Cors__AllowedOrigins:0` 注入允许的前端来源
- **禁止使用通配符 `*`**

## 密码策略

### 复杂度要求（L-1）

通过 `ApplyPasswordPolicy()` FluentValidation 扩展统一约束：

- 最小长度 8 位
- 必须包含大写字母（A-Z）
- 必须包含小写字母（a-z）
- 必须包含数字（0-9）

适用于所有密码校验器：注册、改密、重置、批量导入。

### 随机初始密码（L-2）

- CSV 批量导入使用 `RandomNumberGenerator` 生成 12 位随机密码，禁止使用学号或固定默认密码
- `Student.MustChangePassword = true`，首次登录强制改密

### 强制改密流程（L-2）

- 新增 `/auth/force-change-password` 端点与 `/force-change-password` 页面
- `MustChangePassword = true` 的学生登录后引导至改密页面
- 改密成功后标记置为 `false`

## 审计日志（M-5）

`IAuditService` 记录以下敏感操作，写入 `AuditLog` 实体（用户、IP、UserAgent、操作、目标、时间、附加信息）：

- 登录成功 / 失败
- 密码修改 / 重置
- 2FA 绑定 / 验证
- 用户增删
- CSV 批量导入

> 审计服务容错写入（不影响主业务流程），IP 从 `IHttpContextAccessor` 解析，字段超长自动截断。

## 安全响应头（L-4）

`SecurityHeadersMiddleware` 统一注入：

| 响应头 | 取值 |
|--------|------|
| `Content-Security-Policy` | `default-src 'self'`（按页面需要放宽） |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains`（生产环境） |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `X-XSS-Protection` | 启用 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | 限制摄像头/麦克风/地理位置等敏感能力 |

## 配置安全

| 配置项 | 安全要求 |
|--------|----------|
| `Db:ConnectionString` | appsettings.json 置空，启动校验非空，生产通过 `Db__ConnectionString` 注入（H-5） |
| `Jwt:SecretKey` | Development 置空，DEBUG 自动生成临时密钥，建议 `user-secrets` 管理（L-5） |
| `Cors:AllowedOrigins` | appsettings.json 置空，生产通过 `Cors__AllowedOrigins__0` 注入（M-7） |
| `ConnectionStrings:redis` | JWT 黑名单 / TOTP 重放 / 2FA 锁定依赖，生产必须配置 |

> 敏感配置通过 `dotnet user-secrets`（开发）或环境变量（生产）注入，禁止硬编码或使用默认值。

## 已清查确认安全的攻击面

经第二轮审计确认无新增漏洞的攻击面：

- **注入向量**：SqlSugar 全部使用 lambda 参数化查询，无字符串拼接 SQL；无 Shell 命令注入、模板注入、文件路径穿越、危险反序列化
- **外部交互**：HttpClient 出站调用指向固定 BaseAddress，TOTP/QR 本地计算无外部 HTTP，无 Webhook
- **敏感数据处理**：日志不记录 password/token/TOTP 明文，异常信息不暴露（M-6 除外已修复），DTO 隔离密码字段，BCrypt 哈希自带随机盐
