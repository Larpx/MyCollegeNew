## 开发环境配置（user-secrets）

第二轮安全审计后，`appsettings.json` 中的数据库连接字符串、`appsettings.Development.json` 中的 JWT SecretKey 与 CORS 白名单均已置空，启动时会强制校验。本地开发建议使用 `dotnet user-secrets` 管理敏感配置。

### 配置 API 项目

```bash
cd src/Campus.Attendance.Api

# 设置数据库连接字符串（H-5：appsettings.json 已置空，必须注入）
dotnet user-secrets set "Db:ConnectionString" "DataSource=attendance.db"

# 设置 JWT 密钥（L-5：至少 32 字符）
dotnet user-secrets set "Jwt:SecretKey" "你的开发环境密钥-至少32字符长度"

# 设置 CORS 白名单（M-7：appsettings.json 已置空，必须注入）
dotnet user-secrets set "Cors:AllowedOrigins:0" "https://localhost:7088"

# 查看
dotnet user-secrets list
```

### 配置 Web 项目

```bash
cd ../Campus.Attendance.Web

# JWT 密钥需与 API 一致
dotnet user-secrets set "Jwt:SecretKey" "<与 API 一致的随机字符串>"
dotnet user-secrets set "Cors:AllowedOrigins:0" "https://localhost:7088"
```

> **注意**：DEBUG 模式下若未配置 `Jwt:SecretKey`，将自动生成临时随机密钥，仅用于本地调试。建议显式配置以避免每次启动密钥变化导致已签发 Token 失效。

## 启动顺序

```bash
# ① 运行 API（先启动）
dotnet run --project src/Campus.Attendance.Api

# ② 运行 Web（API 就绪后启动）
dotnet run --project src/Campus.Attendance.Web

# ③ 运行测试
dotnet test src/Campus.Attendance.Tests

# 可选：Aspire 本地编排（一次性启动全部依赖）
dotnet run --project src/Campus.Attendance.AppHost

# 可选：Docker 部署
docker-compose up -d --build
```

## 常见问题

### 端口被占用

修改对应项目的 `Properties/launchSettings.json` 中的 `applicationUrl`，或通过命令行指定：

```bash
dotnet run --project src/Campus.Attendance.Api --urls "https://localhost:7089"
```

### 启动校验失败（连接串/密钥/CORS 为空）

日志出现 `配置项 Db:ConnectionString / Jwt:SecretKey / Cors:AllowedOrigins 为空` 异常：

1. 确认已通过 `user-secrets` 或环境变量注入上述配置
2. 确认 `Jwt:SecretKey` 长度 ≥ 32 字符
3. 确认 `Cors:AllowedOrigins:0` 不是通配符 `*`

### DEBUG 随机密钥提示

DEBUG 模式下未配置 `Jwt:SecretKey` 时会自动生成临时密钥，控制台输出提示。此密钥仅限本地调试，每次启动变化会导致已签发 Token 失效，建议显式配置 `user-secrets`。

### Docker 启动顺序

`docker-compose up` 会按 `db`（健康检查通过）→ `redis` → `api`（健康检查通过）→ `web` 顺序启动。若 `api` 启动失败，先检查 `db` 与 `redis` 容器健康状态。

> 详细说明请参阅 [docs/开发指南.md](../docs/开发指南.md) 与 [docs/部署指南.md](../docs/部署指南.md)。
