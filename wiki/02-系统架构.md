# 系统架构

> 📖 本文档是 Wiki 的一部分 · [🏠 返回首页](./Home.md)

## 整体架构

系统采用垂直切片架构（VSA），按业务功能切分代码而非按技术类型分层。前端通过 BFF 模式调用后端 API，JWT 存储在 HttpOnly Cookie 中。

```
┌──────────────────────────────────────────────────┐
│              Campus.Attendance.Web                │
│           Blazor Web App（静态 SSR + 交互 Server） │
│      JWT 存储在 HttpOnly Cookie (BFF 模式)        │
└──────────────────────┬───────────────────────────┘
                       │ HttpClient + Bearer Token
                       ▼
┌──────────────────────────────────────────────────┐
│              Campus.Attendance.Api                │
│            Minimal APIs + 垂直切片                  │
│  Features/ Auth · Users · Organization · Courses  │
│            Attendance · Leave · Statistics        │
│  MediatR + FluentValidation + Mapster             │
└──────────────────────┬───────────────────────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│   Shared     │ │Infrastructure│ │  ServiceDefaults │
│ 实体/DTO/枚举 │ │SqlSugar/Redis│ │  OTEL/健康检查     │
│ 异常/常量/接口 │ │Token/用户上下文│ │  服务发现/弹性     │
└──────────────┘ └──────────────┘ └──────────────────┘
```

### 分层职责

| 层 | 职责 |
|------|------|
| Web/Admin | Blazor Server BFF，封装 API 调用，管理 HttpOnly Cookie |
| Api | Minimal APIs + VSA，CQRS 分离，统一异常处理与安全响应头 |
| Infrastructure | SqlSugar ORM、Token 生成、当前用户上下文、审计服务 |
| Shared | 实体、DTO、枚举、异常、常量、接口（无外部依赖） |

### 项目依赖关系

```
Api ──▶ Shared + Infrastructure + ServiceDefaults
Web ──▶ Shared + Infrastructure + ServiceDefaults
Infrastructure ──▶ Shared
Tests ──▶ Shared + Infrastructure + Api
AppHost ──▶ Api + Web（编排引用）
```

## 认证流程

### 登录流程

```
用户提交用户名/密码/验证码 → POST /api/v1/auth/login
    │
    ▼
LoginValidator (FluentValidation)
    └─ 校验 LoginRequest.CaptchaToken 非空（H-1 强制生效）
    │
    ▼
LoginHandler
    ├─ 强制校验 captcha token（不通过直接返回 400）
    ├─ 用户不存在时执行 dummy BCrypt Verify 消除时序侧信道（L-3）
    ├─ 查 SystemUser 表（管理员） → BCrypt 验证
    ├─ 查 Teacher 表（教师/辅导员） → BCrypt 验证
    └─ 查 Student 表（学生） → BCrypt 验证
    │
    ▼
TokenService.GenerateToken(...)
    │  Claims: NameIdentifier, Name, Role, user_id, role,
    │          system_user_id（统一主键，H-3）, jti（黑名单撤销，M-3）
    │  过期: 120 分钟
    ▼
服务端将 JWT 写入 HttpOnly Cookie（campus_attendance_token）
    │  HttpOnly = true, Secure = true, SameSite = Strict
    ▼
若 MustChangePassword = true → 返回 mustChangePassword，跳转 /force-change-password
若启用 2FA → 返回 requiresTwoFactor，走 2FA 验证流程
```

### JWT 黑名单（M-3）

- 登出端点 `/api/v1/auth/logout` 调用 `TokenRevocationService.RevokeAsync(jti, expiry)`
- 将 `jti` 写入 `IDistributedCache`，TTL = Token 剩余有效期
- `JwtBearer.Events.OnTokenValidated` 实时检查 `jti` 是否在黑名单，命中则 401
- **依赖 Redis / `IDistributedCache`**，生产环境必须配置

### system_user_id claim（H-3）

JWT 新增 `system_user_id` claim 作为统一用户主键，解决 Admin 角色类型混淆问题：

- `ICurrentUser.UserId`：业务主键（学号/工号/用户名）
- `ICurrentUser.SystemUserId`：统一系统主键（对应 `system_user_id` claim）
- 管理员自删除保护、改密等场景按 `SystemUserId` 比较，避免字符串与数字 Id 混淆

## 2FA 流程（TOTP）

```
绑定阶段（用户已登录）:
    POST /api/v1/auth/2fa-setup
        └─ 生成 TOTP 密钥 → 存入 IDistributedCache 服务端会话（M-4）
        └─ 返回二维码（不再通过非 HttpOnly Cookie 传输密钥）
    POST /api/v1/auth/2fa-verify
        └─ 校验 TOTP 验证码
        └─ 重放保护：已用验证码写入 IDistributedCache，30s 内拒绝重放（M-1）

登录验证阶段:
    POST /api/v1/auth/2fa-challenge
        └─ 独立速率限制：每 IP 每分钟 10 次（M-2）
        └─ 5 次失败锁定
        └─ 同样启用重放保护（M-1）
```

> **死端点清理**：原 `/auth/2fa-complete` 端点未验证即创建会话，已在 H-2 中删除。

## 数据模型关键表

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| `SystemUser` | Id, Username, PasswordHash, Role | 管理员账号 |
| `Teacher` | Id, Username, PasswordHash | 教师/辅导员账号 |
| `Student` | Id, StudentNo, PasswordHash, **MustChangePassword** | 学生账号；`MustChangePassword`（L-2）标记 CSV 导入的随机密码账号需首登强制改密 |
| `AuditLog` | Id, UserId, Action, Target, IpAddress, UserAgent, CreatedAt, Extra | 审计日志实体（M-5），由 `IAuditService` 写入，记录登录/密码/2FA/用户增删/批量导入等敏感操作 |

> 数据库通过 `DbConfig.ProviderType` 在 SQLite（开发）与 MySQL（生产）间切换，SqlSugar CodeFirst 自动建表。

## 中间件管道

```
HTTP 请求
    │
    ▼
HttpsRedirection → HSTS
    │
    ▼
SecurityHeadersMiddleware（L-4）
    └─ 注入 CSP / X-Content-Type-Options / X-Frame-Options / X-XSS-Protection
       Referrer-Policy / Permissions-Policy
    │
    ▼
CORS（白名单 M-7）
    │
    ▼
RateLimiter（全局 + 2FA 独立策略 M-2）
    │
    ▼
JwtBearer 认证
    └─ OnTokenValidated → TokenRevocationService 黑名单校验（M-3）
    │
    ▼
Routing → Endpoint → MediatR 管道
    └─ ValidationBehavior → Handler（可注入 IAuditService M-5）
    │
    ▼
IAuditService 记录敏感操作 → AuditLog 表
```
