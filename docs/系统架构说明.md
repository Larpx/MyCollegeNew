# 系统架构说明

## 1. 垂直切片架构 (VSA)

系统采用垂直切片架构，按业务功能切分代码，而非按技术类型分层。每个功能模块（Auth / Attendance / Leave 等）内包含自身的 Endpoint、Handler、Command/Query、DTO 和 Validator。

```
┌──────────────────────────────────────────────────┐
│              Campus.Attendance.Web                │
│           Blazor Web App（静态 SSR + 交互 Server） │
│      JWT 存储在 HttpOnly Cookie (BFF 模式)        │
└──────────────────────┬───────────────────────────┘
                       │ HttpClient + Bearer Token
                       ▼
┌──────────────────────────────────────────────────┐
│              Campus.Attendance.Api                │
│            Minimal APIs + 垂直切片                  │
│  ┌───────────────────────────────────────────┐   │
│  │  Features/                                │   │
│  │  ├── Auth/         (登录/登出/个人信息)     │   │
│  │  ├── Users/        (学生/教师 CRUD)        │   │
│  │  ├── Organization/ (院系/专业/班级)         │   │
│  │  ├── Courses/      (课程/排课)            │   │
│  │  ├── Attendance/   (会话/签到/点名/二维码)  │   │
│  │  ├── Leave/        (请假申请/审批)         │   │
│  │  └── Statistics/   (统计/趋势/导出)        │   │
│  └───────────────────────────────────────────┘   │
│  MediatR + FluentValidation + Mapster             │
└──────────────────────┬───────────────────────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│   Shared     │ │Infrastructure│ │  ServiceDefaults │
│ 实体/DTO/枚举 │ │SqlSugar/Redis│ │  OTEL/健康检查     │
│ 异常/常量/接口 │ │Token/用户上下文│ │  服务发现/弹性     │
└──────────────┘ └──────────────┘ └──────────────────┘
```

### 项目依赖关系

```
Api ──▶ Shared + Infrastructure + ServiceDefaults
Web ──▶ Shared + Infrastructure + ServiceDefaults
Infrastructure ──▶ Shared
Tests ──▶ Shared + Infrastructure + Api
AppHost ──▶ Api + Web（编排引用）
```

### 切片内文件结构

每个 Feature 切片包含以下文件：

```
Features/{Feature}/
├── {Action}Endpoint.cs      # Minimal API 路由注册
├── {Action}Command.cs        # CQRS 请求（Command/Query）
├── {Action}Handler.cs        # 业务逻辑实现
└── {Action}Validator.cs      # FluentValidation 校验规则
```

切片间禁止直接引用内部 Handler，跨功能调用必须通过 MediatR 发送请求。

## 2. 数据流

### 请求处理流程

```
用户浏览器
    │
    │ ① 点击操作（如查看课表）
    ▼
Blazor Server (Web)
    │
    │ ② ApiClient 从 HttpOnly Cookie 读取 JWT
    │    附加 Authorization: Bearer {token}
    │    HTTP GET http://api:8080/api/v1/schedules/my?week=1
    ▼
API Endpoint (Minimal API)
    │
    │ ③ JwtBearer 中间件验证 Token
    │    角色策略校验（RequireAuthorization）
    │    通过 IMediator 发送 Query
    ▼
MediatR Handler
    │
    │ ④ FluentValidation 管道自动校验
    │    通过 IDbContext 执行数据库操作
    ▼
SqlSugar ORM → MySQL / SQLite
    │
    │ ⑤ 返回数据
    ▼
Handler → Mapster 映射 DTO → Endpoint 返回 Results.Ok(dto)
    │
    ▼
ApiClient 反序列化 → Blazor 渲染 → HTML 推送浏览器
```

### 关键设计点

- **ApiClient 统一封装**: 自动从 Cookie 读取 Token、附加请求头、处理 401/403
- **MediatR 管道**: ValidationBehavior 自动校验 → Handler 执行业务逻辑
- **Mapster 映射**: 编译时生成，Entity ↔ DTO 零反射转换
- **统一响应格式**: 所有 API 返回 `ApiResponse<T>`（Code + Message + Data）
- **ProblemDetails**: 异常返回 RFC 7807 标准格式

## 3. 认证流程（BFF 模式）

### 登录流程

```
用户提交用户名/密码 → POST /api/v1/auth/login
    │
    ▼
LoginHandler
    ├─ 查 SystemUser 表（管理员） → BCrypt 验证
    ├─ 查 Teacher 表（教师/辅导员） → BCrypt 验证
    └─ 查 Student 表（学生） → BCrypt 验证
    │
    ▼
TokenService.GenerateToken(userId, userName, role)
    │  HMACSHA256 签名 JWT
    │  Claims: NameIdentifier, Name, Role, user_id, role
    │  过期: 120 分钟
    ▼
服务端将 JWT 写入 HttpOnly Cookie（campus_attendance_token）
    │  HttpOnly = true, Secure = true, SameSite = Strict
    ▼
返回 LoginResult { Token, UserId, UserName, Role }
```

### 请求认证

```
后续每次 API 调用:
    ApiClient
        ├─ 从 HttpOnly Cookie 读取 Token
        ├─ 附加 Header: Authorization: Bearer {token}
        └─ 发送请求
            │
            ▼
        JwtBearer 中间件验证
            ├─ 验证签名、过期时间、Issuer、Audience
            └─ 构建 ClaimsPrincipal
            │
            ▼
        角色策略校验 → ICurrentUser 上下文注入
```

## 4. 数据库切换

通过 `DbConfig.ProviderType` 配置在 SQLite 与 MySQL 间切换：

| 环境 | ProviderType | 说明 |
|------|-------------|------|
| Development | SQLite | 零配置，文件自动创建 (`attendance.db`) |
| Production | MySQL | 通过环境变量 `Db__ConnectionString` 注入连接字符串 |

SqlSugar CodeFirst 自动建表，启动时由 `DbInitializer.InitializeAsync()` 执行，无需手动迁移。

## 6. 安全设计

| 安全措施 | 实现方式 |
|----------|----------|
| 密码存储 | BCrypt 哈希 + 自动盐值 |
| JWT 认证 | HMACSHA256 签名，ClockSkew 1 分钟 |
| BFF 模式 | JWT 存储在 HttpOnly Cookie，禁止 JS 访问 |
| 安全响应头 | X-Content-Type-Options, X-Frame-Options, X-XSS-Protection |
| 异常处理 | 系统异常返回 ProblemDetails (RFC 7807)，不暴露内部细节 |
| 角色授权 | RequireAdmin / RequireTeacher / RequireStudent / RequireCounselor |
| 防伪令牌 | Blazor 内置 Antiforgery 中间件 |
| 输入验证 | FluentValidation 管道自动校验 |
| 限流 | System.Threading.RateLimiting 固定窗口限流 |
| 响应压缩 | Brotli + Gzip |
| HSTS | 强制 HTTPS 重定向 |
