# 系统架构说明

## 1. 垂直切片架构 (VSA)

系统采用垂直切片架构，按业务功能切分代码，而非按技术类型分层。每个功能模块（Auth / Attendance / Leave 等）内包含自身的 Endpoint、Handler、Command/Query、DTO 和 Validator。

```
┌──────────────────────────────────────────────────┐
│              Campus.Attendance.Web                │
│           Blazor Web App（静态 SSR + 交互 Server） │
│      JWT 存储在 HttpOnly Cookie (BFF 模式)        │
└──────────────────────┬───────────────────────────┘
                       │ HttpClient + Bearer Token
                       ▼
┌──────────────────────────────────────────────────┐
│              Campus.Attendance.Api                │
│            Minimal APIs + 垂直切片                  │
│  ┌───────────────────────────────────────────┐   │
│  │  Features/                                │   │
│  │  ├── Auth/         (登录/登出/个人信息)     │   │
│  │  ├── Users/        (学生/教师 CRUD)        │   │
│  │  ├── Organization/ (院系/专业/班级)         │   │
│  │  ├── Courses/      (课程/排课)            │   │
│  │  ├── Attendance/   (会话/签到/点名/二维码)  │   │
│  │  ├── Leave/        (请假申请/审批)         │   │
│  │  └── Statistics/   (统计/趋势/导出)        │   │
│  └───────────────────────────────────────────┘   │
│  MediatR + FluentValidation + Mapster             │
└──────────────────────┬───────────────────────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│   Shared     │ │Infrastructure│ │  ServiceDefaults │
│ 实体/DTO/枚举 │ │SqlSugar/Redis│ │  OTEL/健康检查     │
│ 异常/常量/接口 │ │Token/用户上下文│ │  服务发现/弹性     │
└──────────────┘ └──────────────┘ └──────────────────┘
```

### 项目依赖关系

```
Api ──▶ Shared + Infrastructure + ServiceDefaults
Web ──▶ Shared + Infrastructure + ServiceDefaults
Infrastructure ──▶ Shared
Tests ──▶ Shared + Infrastructure + Api
AppHost ──▶ Api + Web（编排引用）
```

### 切片内文件结构

每个 Feature 切片包含以下文件：

```
Features/{Feature}/
├── {Action}Endpoint.cs      # Minimal API 路由注册
├── {Action}Command.cs        # CQRS 请求（Command/Query）
├── {Action}Handler.cs        # 业务逻辑实现
└── {Action}Validator.cs      # FluentValidation 校验规则
```

切片间禁止直接引用内部 Handler，跨功能调用必须通过 MediatR 发送请求。

## 2. 数据流

### 请求处理流程

```
用户浏览器
    │
    │ ① 点击操作（如查看课表）
    ▼
Blazor Server (Web)
    │
    │ ② ApiClient 从 HttpOnly Cookie 读取 JWT
    │    附加 Authorization: Bearer {token}
    │    HTTP GET http://api:8080/api/v1/schedules/my?week=1
    ▼
API Endpoint (Minimal API)
    │
    │ ③ JwtBearer 中间件验证 Token
    │    角色策略校验（RequireAuthorization）
    │    通过 IMediator 发送 Query
    ▼
MediatR Handler
    │
    │ ④ FluentValidation 管道自动校验
    │    通过 IDbContext 执行数据库操作
    ▼
SqlSugar ORM → MySQL / SQLite
    │
    │ ⑤ 返回数据
    ▼
Handler → Mapster 映射 DTO → Endpoint 返回 Results.Ok(dto)
    │
    ▼
ApiClient 反序列化 → Blazor 渲染 → HTML 推送浏览器
```

### 关键设计点

- **ApiClient 统一封装**: 自动从 Cookie 读取 Token、附加请求头、处理 401/403
- **MediatR 管道**: ValidationBehavior 自动校验 → Handler 执行业务逻辑
- **Mapster 映射**: 编译时生成，Entity ↔ DTO 零反射转换
- **统一响应格式**: 所有 API 返回 `ApiResponse<T>`（Code + Message + Data）
- **ProblemDetails**: 异常返回 RFC 7807 标准格式

## 3. 认证流程（BFF 模式）

### 登录流程

```
用户提交用户名/密码/验证码 → POST /api/v1/auth/login
    │
    ▼
LoginValidator (FluentValidation)
    └─ 校验 LoginRequest.CaptchaToken 非空（H-1 强制生效）
    │
    ▼
LoginHandler
    ├─ 强制校验 captcha token（不通过直接返回 400）
    ├─ 用户不存在时执行 dummy BCrypt Verify 消除时序侧信道（L-3）
    ├─ 查 SystemUser 表（管理员） → BCrypt 验证
    ├─ 查 Teacher 表（教师/辅导员） → BCrypt 验证
    └─ 查 Student 表（学生） → BCrypt 验证
    │
    ▼
TokenService.GenerateToken(userId, userName, role)
    │  HMACSHA256 签名 JWT
    │  Claims: NameIdentifier, Name, Role, user_id, role, system_user_id, jti
    │    ├─ system_user_id: 统一的用户主键，解决 Admin 角色类型混淆（H-3）
    │    └─ jti: Token 唯一标识，用于黑名单撤销（M-3）
    │  过期: 120 分钟
    ▼
服务端将 JWT 写入 HttpOnly Cookie（campus_attendance_token）
    │  HttpOnly = true, Secure = true, SameSite = Strict
    ▼
返回 LoginResult { Token, UserId, UserName, Role }
```

> **首次登录强制改密**：学生通过 CSV 批量导入时使用随机密码并标记 `MustChangePassword = true`（L-2），
> 登录后跳转 `/force-change-password` 页面强制修改密码。

### 2FA（TOTP）流程

```
绑定阶段:
    POST /api/v1/auth/2fa-setup
        └─ 生成 TOTP 密钥 → 存入 IDistributedCache 服务端会话（M-4）
        └─ 返回二维码（不再通过非 HttpOnly Cookie 传输密钥）
    POST /api/v1/auth/2fa-verify
        └─ 校验 TOTP 验证码
        └─ 重放保护：已用验证码写入 IDistributedCache，30s 内拒绝重放（M-1）

验证阶段:
    POST /api/v1/auth/2fa-challenge
        └─ 独立速率限制：每 IP 每分钟 10 次（M-2）
        └─ 5 次失败锁定，触发账号保护（M-2）
        └─ 同样启用重放保护（M-1）
```

> **死端点清理**：原 `/auth/2fa-complete` 端点未验证即创建会话，已在 H-2 中删除。

### 请求认证

```
后续每次 API 调用:
    ApiClient
        ├─ 从 HttpOnly Cookie 读取 Token
        ├─ 附加 Header: Authorization: Bearer {token}
        └─ 发送请求
            │
            ▼
        JwtBearer 中间件验证
            ├─ 验证签名、过期时间、Issuer、Audience
            ├─ OnTokenValidated: 调用 TokenRevocationService 检查 jti 黑名单（M-3）
            └─ 构建 ClaimsPrincipal
            │
            ▼
        角色策略校验 → ICurrentUser 上下文注入（含 SystemUserId）
```

### JWT 撤销机制（M-3）

```
登出流程:
    POST /api/v1/auth/logout
        └─ TokenRevocationService.RevokeAsync(jti, expiry)
        └─ 将 jti 写入 IDistributedCache，TTL = Token 剩余有效期
        └─ 清除 HttpOnly Cookie

请求拦截:
    JwtBearer Events.OnTokenValidated
        └─ 查询 jti 是否在黑名单 → 是则 401 Unauthorized
```

## 4. 数据库切换

通过 `DbConfig.ProviderType` 配置在 SQLite 与 MySQL 间切换：

| 环境 | ProviderType | 说明 |
|------|-------------|------|
| Development | SQLite | 零配置，文件自动创建 (`attendance.db`) |
| Production | MySQL | 通过环境变量 `Db__ConnectionString` 注入连接字符串 |

> **连接字符串安全（H-5）**：`appsettings.json` 中的 `Db:ConnectionString` 已置空，
> 应用启动时强制校验非空，生产环境通过环境变量 `Db__ConnectionString` 注入，
> 杜绝硬编码与默认凭据泄露风险。

SqlSugar CodeFirst 自动建表，启动时由 `DbInitializer.InitializeAsync()` 执行，无需手动迁移。

### 关键数据模型

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| `SystemUser` | Id, Username, PasswordHash, Role | 管理员账号 |
| `Teacher` | Id, Username, PasswordHash | 教师/辅导员账号 |
| `Student` | Id, StudentNo, PasswordHash, **MustChangePassword** | 学生账号；`MustChangePassword`（L-2）标记 CSV 导入的随机密码账号需首次登录强制改密 |
| `AuditLog` | Id, UserId, Action, Target, IpAddress, UserAgent, CreatedAt, Extra | 审计日志实体（M-5），由 `IAuditService` 写入，记录登录/密码/2FA/用户增删/批量导入等敏感操作 |

## 6. 安全设计

| 安全措施 | 实现方式 |
|----------|----------|
| 密码存储 | BCrypt 哈希 + 自动盐值 |
| 密码策略 | `ApplyPasswordPolicy()` FluentValidation 扩展，至少 8 位、含大小写字母和数字（L-1） |
| 学生默认密码 | CSV 批量导入使用 `RandomNumberGenerator` 生成 12 位随机密码 + `MustChangePassword` 标记（L-2） |
| JWT 认证 | HMACSHA256 签名，ClockSkew 1 分钟，Claims 含 `system_user_id`（H-3）与 `jti`（M-3） |
| JWT 撤销 | `TokenRevocationService` + `/auth/logout` + `OnTokenValidated` 黑名单检查（M-3） |
| BFF 模式 | JWT 存储在 HttpOnly Cookie，禁止 JS 访问 |
| 登录验证码 | `LoginRequest.CaptchaToken` 必填，`LoginValidator` + `LoginHandler` 强制校验（H-1） |
| 时序侧信道防护 | 用户不存在时执行 dummy BCrypt Verify，消除登录耗时差异（L-3） |
| 2FA 重放保护 | TOTP 已用验证码写入 `IDistributedCache`，30s 内拒绝重放（M-1） |
| 2FA 速率限制 | 独立限流：每 IP 每分钟 10 次 + 5 次失败锁定（M-2） |
| 2FA 密钥存储 | TOTP 密钥/二维码改用 `IDistributedCache` 服务端会话存储，不再通过非 HttpOnly Cookie 传输（M-4） |
| 死端点清理 | 删除未验证即创建会话的 `/auth/2fa-complete` 端点（H-2） |
| 审计日志 | `IAuditService` 记录登录成败、密码修改/重置、2FA 绑定/验证、用户增删、批量导入等敏感操作，写入 `AuditLog` 实体（M-5） |
| CSV 异常脱敏 | 批量导入异常不返回 `ex.Message` 给客户端（M-6） |
| 安全响应头 | `SecurityHeadersMiddleware` 输出 X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, **CSP, HSTS, Referrer-Policy, Permissions-Policy**（L-4） |
| CORS 白名单 | `Cors:AllowedOrigins` 配置项置空，仅允许显式配置的来源（M-7） |
| 异常处理 | 系统异常返回 ProblemDetails (RFC 7807)，不暴露内部细节 |
| 角色授权 | RequireAdmin / RequireTeacher / RequireStudent / RequireCounselor |
| 防伪令牌 | Blazor 内置 Antiforgery 中间件 |
| 输入验证 | FluentValidation 管道自动校验 |
| 限流 | System.Threading.RateLimiting 固定窗口限流 |
| 响应压缩 | Brotli + Gzip |
| HSTS | 强制 HTTPS 重定向 |
| 配置安全 | `appsettings.json` 数据库连接字符串置空、`appsettings.Development.json` JWT SecretKey 置空，启动校验；开发环境用 `dotnet user-secrets` 管理（H-5、L-5） |

### 中间件管道

```
HTTP 请求
    │
    ▼
HttpsRedirection → HSTS
    │
    ▼
SecurityHeadersMiddleware（L-4）
    └─ 注入 CSP / X-Content-Type-Options / X-Frame-Options / X-XSS-Protection
       Referrer-Policy / Permissions-Policy
    │
    ▼
CORS（白名单 M-7）
    │
    ▼
RateLimiter（全局 + 2FA 独立策略 M-2）
    │
    ▼
JwtBearer 认证
    └─ OnTokenValidated → TokenRevocationService 黑名单校验（M-3）
    │
    ▼
Routing → Endpoint → MediatR 管道
    └─ ValidationBehavior → Handler（可注入 IAuditService M-5）
    │
    ▼
IAuditService 记录敏感操作 → AuditLog 表
```
