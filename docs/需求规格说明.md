# 需求规格说明

## 背景

本项目是针对高校学生上课考勤管理的现代化系统重构。原系统为 ASP.NET WebForms + SQL Server 单体架构，存在硬编码 SQL、明文密码、无分层、不支持移动端等弊端。重构基于 .NET 10 + 垂直切片架构 (VSA) 重新设计，围绕课堂签到、点名、请假三大核心场景，提供管理员、教师、学生三端能力。

## 角色与端划分

| 端 | 角色 | 核心场景 |
|----|------|----------|
| 管理员端 | 系统管理员 | 组织架构管理、用户管理、全局统计、报表导出 |
| 教师端 | 任课教师 | 课堂点名、考勤记录、课程管理 |
| 教师端 | 辅导员 | 班级管理、请假审批、班级考勤统计 |
| 学生端 | 学生 | 快捷签到、考勤查询、请假申请、课表查看 |

> 辅导员与任课教师共享教师端 UI，通过角色权限控制功能可见性。

## 功能需求

### 多端统一登录与角色路由

系统提供统一登录入口，用户使用工号/学号 + 密码登录，系统根据角色自动路由至对应端，并签发 JWT Token。

**验收标准**:
- 学生登录后跳转学生端首页
- 教师/辅导员登录后跳转教师端首页
- 管理员登录后跳转管理员仪表盘
- 角色越权访问返回 403

### 二维码动态签到

教师发起考勤会话时生成动态二维码（30 秒刷新），学生扫码完成签到，防止代签。

**签到状态判定**:
- 会话开始后 5 分钟内签到 → 正常
- 5-15 分钟内签到 → 迟到
- 超过 15 分钟未签到 → 缺勤（教师可手动补签）

**验收标准**:
- 教师可创建考勤会话，生成含签名 Token 的二维码
- 二维码每 30 秒自动刷新，旧 Token 失效
- 学生扫码签到成功，返回签到状态
- Token 过期后签到被拒绝

### 一键点名与随机点名

**验收标准**:
- 一键点名：批量标记全班学生为出勤
- 随机点名：随机抽取学生，避免连续重复
- 教师可单独修改学生考勤状态

### 请假审批流

学生提交请假 → 辅导员审批 → 审批通过后自动联动更新考勤记录。

**验收标准**:
- 学生可提交请假申请（类型、时间、原因）
- 辅导员可查看待审批列表并审批（通过/驳回）
- 审批通过后，请假时间内的考勤记录自动标记为「请假」

### 学生快捷操作

学生端首页首屏展示三个快捷入口：快捷签到、请假申请、我的考勤。移动端优先设计。

**验收标准**:
- 首页三个快捷卡片 1 步可达
- 卡片适配移动端触控（最小高度 80px）

### 统计与报表

**验收标准**:
- 管理员全局统计：全校出勤率、院系排名、趋势分析
- 教师班级统计：按课程/班级维度统计
- 学生个人统计：本学期出勤率、迟到/缺勤/请假次数
- 支持 Excel 报表导出

### 移动端响应式

**验收标准**:
- 学生端移动端优先，单列布局
- 触控目标最小 44x44px
- 教师/管理员端桌面优先，移动端兼容

## 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | API 响应时间 < 500ms（P95） |
| 安全 | JWT + BCrypt 密码哈希 + HttpOnly Cookie + 防伪令牌 |
| 可靠性 | 全局异常处理，系统异常不暴露细节 |
| 可维护性 | 垂直切片架构，按功能模块组织代码 |
| 可扩展性 | SqlSugar 多数据库切换，Redis 可插拔缓存 |
| 部署 | Docker Compose 一键启动，Linux 目标环境 |
| 日志 | Serilog 结构化日志 + OpenTelemetry 追踪 |
| 文档 | Scalar 自动生成 OpenAPI 文档 |
