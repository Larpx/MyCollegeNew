## 开发环境配置（user-secrets）

第二轮安全审计（L-5）后，`appsettings.Development.json` 中的 `Jwt:SecretKey` 已置空，`Campus.Attendance.Api.csproj` 添加了 `UserSecretsId`，DEBUG 模式下会自动生成随机密钥。建议使用 `dotnet user-secrets` 显式管理本地密钥，避免随机密钥每次启动变化导致已签发 Token 失效：

```bash
# 初始化 user-secrets（csproj 已配置 UserSecretsId，可跳过）
cd src/Campus.Attendance.Api
dotnet user-secrets init

# 设置 JWT 密钥（至少 32 字符）
dotnet user-secrets set "Jwt:SecretKey" "你的开发环境密钥-至少32字符长度"

# 设置数据库连接字符串（H-5：appsettings.json 中已置空，生产用环境变量 Db__ConnectionString）
dotnet user-secrets set "Db:ConnectionString" "Server=localhost;Database=attendance_dev;..."

# 查看
dotnet user-secrets list
```

> 注意：`appsettings.json` 中的 `Db:ConnectionString` 与 `appsettings.Development.json` 中的 `Jwt:SecretKey` 已置空，
> 启动时会强制校验，缺失则抛出异常阻止启动。

## 如何添加新功能

1. 在 `Api/Features/{Feature}/` 下创建子目录（如 `CreateXxx/`）
2. 创建文件：
   - `CreateXxxEndpoint.cs` — Minimal API 路由注册
   - `CreateXxxCommand.cs` — CQRS 请求
   - `CreateXxxHandler.cs` — 业务逻辑
   - `CreateXxxValidator.cs` — FluentValidation 校验
3. 在 `Shared/Features/{Feature}/` 下创建 DTO
4. 在 `Features/Endpoints.cs` 中注册路由模块
5. 编写对应的单元测试

## 代码规范

- **命名**：类/方法 PascalCase，参数/变量 camelCase，私有字段 `_camelCase`，接口 `I` 前缀
- **异步**：公共方法异步优先，Handler 和 Endpoint 接收 `CancellationToken`
- **DI**：构造函数注入，配置使用 `IOptions<T>`
- **时间**：统一使用 `DateTime.UtcNow`
- **异常**：业务异常用 `BusinessException`，系统异常统一返回 `ProblemDetails`
- **日志**：`ILogger<T>` 结构化日志

## 安全开发规范

### 密码策略（L-1）

所有涉及密码设置的 Validator（注册、改密、重置、批量导入）必须调用 `ApplyPasswordPolicy()` 扩展方法，统一密码复杂度要求：

- 位置：`Api/Validation/PasswordValidationExtensions.cs`
- 规则：至少 8 位、必须包含大写字母、小写字母和数字
- 用法：

```csharp
public class ChangePasswordValidator : AbstractValidator<ChangePasswordCommand>
{
    public ChangePasswordValidator()
    {
        RuleFor(x => x.NewPassword).ApplyPasswordPolicy();
        // 其他规则...
    }
}
```

> 禁止在 Validator 中手写密码正则，必须复用 `ApplyPasswordPolicy()` 保证策略一致。

### 审计日志（M-5）

敏感操作必须通过 `IAuditService` 记录审计日志，写入 `AuditLog` 实体。需记录的操作包括：

- 登录成功 / 失败
- 密码修改 / 重置
- 2FA 绑定 / 验证
- 用户增删
- CSV 批量导入

```csharp
public class ChangePasswordHandler : IRequestHandler<ChangePasswordCommand, Result>
{
    private readonly IAuditService _auditService;

    public async Task<Result> Handle(ChangePasswordCommand cmd, CancellationToken ct)
    {
        // ... 业务逻辑 ...
        await _auditService.LogAsync("password.change", targetUserId, ct);
        return Result.Success();
    }
}
```

> `IAuditService.LogAsync(action, target, ct)` 会自动记录当前 `ICurrentUser` 的 UserId、IP、UserAgent 等上下文信息。

### CSV 批量导入（L-2、M-6）

学生 CSV 批量导入开发规范：

- **随机密码**：使用 `System.Security.Cryptography.RandomNumberGenerator` 生成 12 位随机密码，禁止使用学号或固定默认密码
- **强制改密标记**：导入时 `Student.MustChangePassword = true`，首次登录强制跳转 `/force-change-password`
- **异常脱敏（M-6）**：导入过程中捕获的异常禁止将 `ex.Message` 原样返回给客户端，应返回通用错误信息，详细信息仅写入日志
- **审计记录**：导入完成后通过 `IAuditService` 记录批量导入操作

### 安全编码规范

- **异常脱敏**：面向客户端的响应禁止包含 `ex.Message`、堆栈、内部字段名等敏感信息，统一返回通用错误（参见 M-6）
- **安全响应头**：`SecurityHeadersMiddleware`（L-4）已统一注入 CSP / HSTS / X-Content-Type-Options / X-Frame-Options / X-XSS-Protection / Referrer-Policy / Permissions-Policy，禁止在控制器中重复设置或覆盖
- **CORS**：跨域来源通过 `Cors:AllowedOrigins` 白名单配置（M-7），禁止使用 `AllowAnyOrigin`
- **2FA 密钥传输**：TOTP 密钥与二维码必须通过 `IDistributedCache` 服务端会话存储（M-4），禁止通过非 HttpOnly Cookie 传输
- **JWT 撤销**：登出操作必须调用 `TokenRevocationService.RevokeAsync(jti, expiry)`（M-3），禁止仅清除客户端 Cookie
- **配置校验**：数据库连接字符串、JWT SecretKey 启动时强制校验非空（H-5、L-5），禁止硬编码或使用默认值

## 架构原则

- **垂直切片**：每个功能模块代码集中在同一目录
- **CQRS**：Command/Query 分离，通过 MediatR 解耦
- **防重复**：共享代码提取到 `Shared`，禁止跨切片复制
- **切片间通信**：通过 MediatR 发送请求，禁止直接引用 Handler
