# 测试项目说明

测试项目，基于 xUnit 的单元测试，覆盖 API Features 中每个切片的 Handler 业务逻辑。

## 项目职责

- 对垂直切片中的 Handler 进行单元测试
- 使用内存 SQLite 数据库隔离测试（TestDbContext）
- 遵循 AAA 模式（Arrange-Act-Assert）
- 覆盖正常流程、边界条件与异常场景

## 测试基础设施

第二轮安全审计修复后，测试基础设施同步更新以适配新依赖：

### TestDbContext

- 内存 SQLite 数据库上下文，启动时执行 CodeFirst 建表
- `student` 表新增 `MustChangePassword` 列（L-2），构造测试数据时需显式设置该字段
- `audit_log` 表新增（M-5），供 `IAuditService` 写入（测试中通常用 `NullAuditService` 跳过）

### TestCurrentUser

实现 `ICurrentUser` 接口，第二轮审计（H-3）后新增 `SystemUserId` 属性：

- `UserId`：业务主键（如学号、工号）
- `SystemUserId`：统一系统主键，对应 JWT 中的 `system_user_id` claim，解决 Admin 角色类型混淆
- `Role` / `UserName` / `IsAuthenticated`：原有属性

### NullAuditService

`IAuditService` 的空实现（M-5），`LogAsync` 直接返回 `Task.CompletedTask`，不写入数据库。
默认在测试 DI 容器中注册，使被测 Handler 的 `IAuditService` 参数无副作用。需要断言审计行为时，
可替换为 `Mock<IAuditService>` 并验证 `LogAsync` 调用。

### TestDistributedCache

简单的内存字典实现 `IDistributedCache`，用于以下测试场景：
- TOTP 重放保护测试（M-1）：写入已用验证码，验证重放被拒绝
- JWT 黑名单测试（M-3）：写入 jti，验证 `TokenRevocationService` 拦截
- 2FA 密钥会话测试（M-4）：验证 TOTP 密钥从服务端会话读取

### 测试构造函数变更

以下 Handler 构造函数新增 `IAuditService` 参数（M-5），测试构造时需传入 `NullAuditService.Instance` 或 Mock：

| Handler | 新增参数 | 说明 |
|---------|----------|------|
| `LoginHandler` | `IAuditService` | 记录登录成败（H-1 验证码校验后） |
| `ChangePasswordHandler` | `IAuditService` | 记录密码修改（H-4 Admin 分支兼容 Id/Username） |
| `StudentHandlers`（增删/批量导入） | `IAuditService` | 记录用户增删与批量导入 |

### LoginHandler 测试注意事项（H-1）

H-1 修复后登录强制校验验证码 token，`AuthServiceTests` 中登录用例需：

1. 在 `IDistributedCache` 中预置有效的验证码 token（key 约定为 `captcha:{token}`）
2. `LoginRequest.CaptchaToken` 必填且非空，否则 `LoginValidator` 直接校验失败
3. 缺失 token 的用例应断言返回 400，而非登录成功

### 安全审计相关测试要点

第二轮安全审计修复引入的测试关注点：

- **H-1 验证码强制校验**：登录成功用例必须预置有效 captcha token；缺失/无效 token 用例断言 400
- **H-3 SystemUserId**：`TestCurrentUser` 构造时设置 `SystemUserId`，验证 `ChangePasswordHandler` Admin 分支按 Id/Username 正确查询（H-4）
- **L-2 强制改密**：`MustChangePassword = true` 的学生登录后应触发改密流程
- **M-1 重放保护**：同一 TOTP 验证码二次提交应被拒绝
- **M-3 JWT 黑名单**：`TokenRevocationService.RevokeAsync` 后，`IsRevokedAsync(jti)` 返回 true
- **M-5 审计调用**：敏感操作后验证 `IAuditService.LogAsync` 被调用（用 `Mock<IAuditService>.Verify`）
