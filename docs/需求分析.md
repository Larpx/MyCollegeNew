## 引言

### 编写目的

本项目针对高校学生上课考勤管理，采用先进的网络技术，代替以往由学生手写签到表的考勤记录方式，由系统准确地将学生的考勤信息进行汇总处理并存储。学生登录系统后，可方便地查看自己的考勤情况，同时减少学生管理部门工作人员的工作量。

### 背景

考勤管理在学生管理过程中扮演着重要角色，考勤管理的效率对教学起到不可估量的作用。传统纸质考勤模式存在以下弊端：

1. 考勤信息不方便整体管理与汇总统计
2. 学生请假流程繁琐，信息对任课老师不透明
3. 学生无法查看自己整个学期的出勤统计
4. 班主任/辅导员难以查看本班学生出勤情况
5. 院系领导、学校领导难以把握学生出勤整体状况
6. 学生管理部门无法有效利用考勤数据进行分析辅助决策

### 预期目标

- 实现学生考勤缺席情况的全面计算机处理，提高工作效率
- 及时提供学生考勤统计信息，提高管理水平
- 与学生共享信息，满足信息处理的准确性、一致性、时效性
- 为决策者提供有效信息，辅助做出正确决策
- 方便学生及老师操作
- 数据实现自动更新、定期汇总

## 系统设计原则

1. **使用方便性和可维护性**：功能模块划分合理，不同角色用户易于操作
2. **功能完善性**：系统功能完善，准确表示业务数据
3. **可靠性**：系统出错时有相应提示，不会因误操作导致崩溃和数据丢失
4. **数据安全性**：登录、权限、数据库操作均有验证和保护措施
5. **可扩展性**：适应数据库结构、架构变化和功能调整的需求

## 用户角色分析

根据对学生考勤系统的功能区分，系统划分为四大角色模块：

| 角色 | 核心职责 |
|------|----------|
| **系统管理员** | 管理院系专业信息、班级信息、用户管理、统计报表、数据库维护 |
| **任课教师** | 课堂考勤发起、二维码签到、点名、考勤记录查询、课表管理 |
| **辅导员** | 下属班级和学生信息查询、考勤信息修改、请假审批、数据导出 |
| **学生** | 扫码签到、个人信息修改、请假申请、考勤信息查询 |

## 系统功能需求

### 前端功能（面向学生、教师、辅导员）

用户登录系统后，根据角色进入不同页面，执行相应功能：

- **学生**：扫码签到、请假申请、考勤查询、课表查看
- **任课教师**：考勤会话创建、二维码生成、一键点名、随机点名、考勤记录查询
- **辅导员**：请假审批、班级考勤统计、学生名单导出

### 后端功能（面向管理员）

管理员登录后执行数据库管理操作：

- 院系/专业/班级组织架构管理
- 学生/教师/辅导员账号管理
- 课程与排课管理
- 全局考勤统计与报表导出

## 技术实现

### 原始方案

原毕业设计采用 ASP.NET WebForms + SQL Server 2005 + ADO.NET 直连数据库。

### 重构方案

基于 .NET 10 全新重构，采用以下技术栈：

| 维度 | 技术选型 |
|------|---------|
| 运行时 | .NET 10 |
| 架构 | 垂直切片架构 (VSA) + CQRS |
| API 风格 | Minimal APIs |
| ORM | SqlSugar Core（SQLite 开发 / MySQL 生产） |
| 认证 | JWT Bearer Token + BCrypt |
| 前端 | Blazor Web App（SSR + InteractiveServer） |
| 文档 | Scalar |
| 日志 | Serilog |
| 部署 | Docker Compose + Linux |

### 数据库设计

系统包含 11 张核心数据表：

| 表名 | 说明 |
|------|------|
| department | 院系基本信息 |
| major | 专业基本信息 |
| class | 班级基本信息 |
| student | 学生基本信息（软删除） |
| teacher | 教师/辅导员基本信息（软删除） |
| system_user | 系统管理员用户（软删除） |
| course | 课程信息 |
| course_schedule | 排课信息 |
| attendance_session | 考勤会话 |
| attendance_record | 考勤记录 |
| leave_request | 请假申请记录 |
| audit_log | 操作审计日志 |

所有涉及用户信息的表均添加软删除标记，提高数据安全性和使用灵活性。

## 可行性分析

- **技术可行性**：.NET 10 + SqlSugar + Blazor 为成熟技术栈，有大量成功案例
- **经济可行性**：B/S 架构部署简单，对软硬件要求低，几乎不需用户培训
- **法律可行性**：系统拥有自主知识产权，未使用违法软件
